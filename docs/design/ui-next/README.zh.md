# Falcon UI · ui-next 设计原型

> 本目录是**当前唯一保留的新一版设计**，供逐屏审查。它把「本机 Falcon 现有界面」与「跨设备 / 账号 / 分享 / NAS 规划」合并成一套可交互原型。
>
> - 默认主题色：**暖橙**（延续现行品牌，不改默认）
> - 可切换主题色：**冷蓝** / **石墨绿**
> - 双模式：**浅色 / 深色 / 跟随系统**
> - 铁律沿用：**只做原型，不动生产代码**

## 怎么审查

双击 `index.html` 用浏览器打开即可（纯静态，无依赖、无需构建）。

- 顶部工具条：点色块切主题色，点「浅色 / 深色」切模式——**所有界面同步换色**，可直接对比三套主题在同一界面的观感。
- 左侧导航：逐屏点击审查。每项对应一个界面，共 **22 屏**（含 6 个弹层预览 + 1 个 Web 端 + 1 个 Windows 托盘）。
- 键盘 `←` / `→`：按顺序在界面间翻页。
- 界面内的开关、复选、分段按钮、匹配码输入框都可点击操作，方便验证交互态。

## 主题系统（关键设计决策）

早期设计把三个方向当作**三选一竞品方案**并行展示。本版把它们收敛为**同一个产品内的可切换主题色**：布局、组件、间距、交互完全一致（纯 token 换肤），用户按需选颜色。

| token 角色 | warm 橙（默认）浅 / 深 | cold 蓝 浅 / 深 | graphite 绿 浅 / 深 |
|---|---|---|---|
| window | `#f6f4f1` / `#16120f` | `#f4f6f8` / `#131519` | `#f4f7f5` / `#0f1214` |
| card | `#ffffff` / `#221c16` | `#ffffff` / `#1b1e24` | `#ffffff` / `#161b1e` |
| text | `#292524` / `#f7f2ec` | `#1e252c` / `#f5f7fa` | `#1b231f` / `#eef2f0` |
| accent | `#c2410c` / `#ffa07a` | `#2f6fd0` / `#5b9df5` | `#0b7d59` / `#34d399` |
| accent 上文字 | `#ffffff` / `#27140a` | `#ffffff` / `#0d1a2b` | `#ffffff` / `#052017` |

- 三方向色值沿用早期 token 表，对比度按 WCAG AA 校验（每方向 24 对检查全部 ≥ 4.5:1）。
- 顶栏 falcon logo 的鲑橙 `#ffa07a` 是品牌锚点（烧在 SVG 里），三主题下保持不变。
- 派生 token：`--accent-soft` / `--accent-ring` / `--track` / 状态色（ok/warn/err/info），均按方向 accent 派生，换肤时同步切换。
- 主题切换入口在**设置页 → 外观**：主题色（暖橙/冷蓝/石墨绿）+ 主题模式（浅色/深色/**跟随系统**）。跟随系统时按 `prefers-color-scheme` 实时应用；顶部审查工具条是评审用的全局控制，与设置页双向联动。

| 屏 | 界面 | 说明 |

| 2 | 下载中 · 列表视图 | 同一数据的表格视图，七列；**默认进入列表视图** |
| 3 | 已完成 | 完成列表、做种态、保存位置 |
| 4 | 资源发现 | 关键词 + 大小筛选 + 相关度排序 + 一键下载；已启用资源站默认折叠为图标 |
| 5 | 云盘空间 | S3/COS 与 NAS 连接卡、文件列表 |
| 6 | 回收站 | 7 天保留期、还原/彻底删除 |
| 7 | 偏好设置 | 外观 / 剪切板 / 下载 / 种子（含 Daemon RPC） |
| 8 | 添加下载任务（弹层） | URL / 保存 / 高级（连接数、做种、UA、Referer、Cookie） |

**跨设备与节点（物） / 账号与分享（人）**

| 屏 | 界面 | 说明 |
|---|---|---|
| 9 | 跨设备 | 替换原「我的设备」；5 项同步开关 + 我的设备（匹配码）+ 隔空传送快捷入口 |
| 10 | 展示传送码（弹层） | 二维码 + 6 位码同屏；一次性 120 秒、复制、刷新；给设备或给他人 |
| 11 | 匹配码配对（弹层） | 扫码 / 手动输入切换（同一串码）；扫码更快、手输兜底 |
| 12 | NAS 与路由 | 飞牛 / OpenWrt / 通用 NAS；能力标签（WebDAV/SMB/SFTP/原生包） |
| 13 | 添加 NAS 节点（弹层） | 预设 + 协议层参数（WebDAV/SMB/SFTP/S3） |
| 14 | 账号 | 后续阶段 · 个人中心：资料卡、统计、安全、演进路径 |
| 15 | 好友 | 后续阶段 · 匹配码加好友、好友请求、好友列表与直传 |
| 16 | 隔空传送 | 账号与分享下的独立入口；发送/接收同一串码，接收方含我的设备、好友、一次性会话 |
| 17 | 分享组 | 后续阶段 · 把我的设备与好友设备编入共享域；成员/权限/key epoch |
| 18 | 分享记录 | 后续阶段 · 隔空传送与分组分享的追溯，不保留码本身 |
| 19 | 登录（弹层） | 复用现有登录弹窗；第一期可隐藏入口 |
| 20 | 编辑资料（弹层） | 昵称、头像、只读 Falcon ID |
| 21 | NAS / 路由版 Web 管理 | 常驻节点最小集：任务 + 存储 + 配对，仅局域网 |
| 22 | Windows 系统托盘 | 仅 Windows：常驻图标（空闲/下载/暂停/完成四态）+ 右键菜单 + 悬浮速度窗；macOS 为菜单栏另一套，本版不出图 |

> 弹层预览共 6 个：屏 8 添加下载任务、屏 10 展示传送码、屏 11 匹配码配对、屏 13 添加 NAS 节点、屏 19 登录、屏 20 编辑资料。
>
> **配对机制**：扫码与手动输入是同一串 6 位码的两种形态，配对流程完全相同（syncbond / SPAKE2，端到端加密，中继看不到码与密钥）。扫码更快、手输兜底。

## 讨论确认的设计决策

### 账号与分享（命名与语义）

- 导航分组定为**「账号与分享」**，不再使用「账号与关系」。「跨设备与节点」管**物**，「账号与分享」管**人**；分享组是两者的连接点（组内既有我的设备，也有好友设备）。
- 隔空传送归属「账号与分享」：它是一个**分享动作**，与跨设备共用同一套 syncbond 匹配码，不做两套机制；跨设备页保留设备视角的快捷入口。

### 传输发现协议取舍

| 能力 | 结论 | 对资源发现的处理 |
|---|---|---|
| LocalSend | 公开协议 v2/v2.2（UDP 组播 `224.0.0.167:53317` 发现 + HTTP(S) REST `53317` 传输，支持证书指纹 / PIN）。可兼容实现为 LocalSend 成员，与匹配码互补。 | 不混入资源站列表；附近设备放在隔空传送 / 通道设置，或作为全局搜索的「其他设备」数据源 |
| AirDrop | AWDL 为 Apple 私有协议，第三方普通应用不能协议级接入。只做「打开系统分享面板」入口；Android 侧借 Quick Share 互通。 | 资源发现里最多是一个系统分享按钮，不出现设备列表 |
| DHT | 适合做 BitTorrent 的底层 peer 发现（提升资源结果的 peer 数与可信度），不适合做关键词资源站，也不建议第一期自建 DHT 发现 Falcon 节点。 | 结果里可显示「DHT 节点数 / 来源：DHT + Tracker + PEX」，不加新页面 |

- 资源发现页保持**纯内容搜索**。附近设备若要进入，采用两种轻量方式：全局搜索的「其他设备」分类，或资源发现页的「附近设备」入口卡（点击跳隔空传送），不做成伪资源站。
- 现成库评估：LocalSend 优先用 Qt 原生（`QUdpSocket` + `QNetworkAccessManager` + `QSslCertificate::digest()`），无第三方依赖；DHT 可选 `mainline`（Rust, MIT）或 `libtorrent-rasterbar`（C++/BSD）；不引入 AWDL 逆向库。

### 平台差异

- Windows：系统托盘常驻 + 右键菜单 + 悬浮速度窗，形态参考迅雷（屏 22）。
- macOS：使用菜单栏图标与下拉菜单，遵循系统状态栏规范；与 Windows 托盘是两套实现，本版只标注差异。

## 设计图导出

`src/public/design/ui-next/screens/` 下是原型导出的静态图：

- 3 主题色 × 亮/暗 × 22 屏 = **132 张 PNG**；目录名如 `warm-light`、`cold-dark`。
- 文件名序号为导出批次号，界面名称见文件名后半段；README 与文档站引用这些图片。
